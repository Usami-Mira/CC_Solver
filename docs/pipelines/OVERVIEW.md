# Pipeline 架构总览

## 核心思想

我们构建的不是一个固定的解题流程，而是一个**策略库**。不同的问题需要不同的思维方式。

就像人类解决问题时：
- 简单的题 → 直接做
- 有多种解法的题 → 试试看哪个最好
- 开放的题 → 一步步探索
- 复杂的题 → 多角度讨论
- 完全未知的题 → 系统性试错

系统提供 5 种策略，对应 5 种思维方式。

---

## 5 种 Pipeline

### 1. Standard — 直接求解

**思维模式：** "我知道怎么做，按步骤来"

**流程：**
```
分析问题 → 制定计划 → 执行求解 → 审查验证
                ↑                    ↓
                └── 有问题？修正 ←──┘
```

**什么时候用：** 标准竞赛题，有明确解法

---

### 2. Parallel Paths — 多路并行

**思维模式：** "这题有好几种做法，都试试，挑最好的"

**流程：**
```
分析问题
    ↓
生成多个策略（解析法、数值法、近似法...）
    ↓
同时执行所有策略
    ↓
比较结果，选择最优
```

**什么时候用：** 有多种可能解法，想比较选择

---

### 3. Iterative — 迭代探索

**思维模式：** "不确定怎么做，先试试看，根据结果调整"

**流程：**
```
提出问题 → 提出假设 → 实验验证 → 评估进展
    ↑                              ↓
    ├── 有希望 → 继续细化 ←────────┘
    ├── 死胡同 → 换方向 ←──────────┘
    └── 部分成功 → 提取有用部分 ←──┘
```

**什么时候用：** 开放性问题，需要通过实验逼近答案

---

### 4. Debate — 多专家辩论

**思维模式：** "这问题太复杂，需要多个人从不同角度看"

**流程：**
```
多位专家独立分析
    ↓
互相辩论，指出问题
    ↓
达成共识，制定方案
    ↓
执行方案
```

**什么时候用：** 跨领域问题，需要多角度分析

---

### 5. Tree Search — 树状搜索

**思维模式：** "完全不知道怎么做，系统性试错，记录所有尝试"

**流程：**
```
生成探索树（多个可能的方向）
    ↓
选择一个方向
    ↓
快速验证（量纲、极限、守恒）
    ↓
有希望？
  ├── 是 → 深入计算
  │         ↓
  │       成功？→ 完成
  │         ↓
  │       失败 → 回溯，试下一个
  │
  └── 否 → 回溯，试下一个
```

**什么时候用：** 前沿研究，高度不确定

---

## 如何选择 Pipeline

```
问题类型？
│
├── 我知道怎么做
│   └── Standard
│
├── 我知道有几种做法
│   └── Parallel Paths
│
├── 我不确定，需要试试
│   └── Iterative
│
├── 这问题太复杂，需要多角度
│   └── Debate
│
└── 完全不知道怎么做
    └── Tree Search
```

---

## 共同原则

所有 Pipeline 都遵循：

1. **计划先行** — 先想清楚再做（除了 Iterative 边做边想）
2. **验证把关** — 每个方案都要经过审查
3. **记录过程** — 用 Git 追踪所有变更
4. **断点续传** — 随时可以中断，下次继续
5. **权限隔离** — 不同角色有不同权限
