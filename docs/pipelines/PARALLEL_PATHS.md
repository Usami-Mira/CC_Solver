# Parallel Paths — 多路并行

## 核心思想

"条条大路通罗马，但我想找到最短的那条。"

当一个问题有多种可能的解法时，与其猜测哪个最好，不如都试试，然后比较。

---

## 流程图

```
第一步：头脑风暴
─────────────────────────────────
分析问题，想出 2-3 个不同的策略

比如：
  • 策略 A：用拉格朗日力学（解析）
  • 策略 B：数值模拟（计算）
  • 策略 C：量纲估算（近似）


第二步：同时执行
─────────────────────────────────
三个策略同时进行，互不干扰

策略 A → 制定计划 → 执行求解 → 审查
策略 B → 制定计划 → 执行求解 → 审查
策略 C → 制定计划 → 执行求解 → 审查


第三步：比较选择
─────────────────────────────────
收集三个结果，对比分析：

  • 哪个通过了审查？
  • 哪个精度最高？
  • 哪个最简洁优雅？
  • 结果是否一致？（一致则可信度高）

选择最优方案，或者融合多个方案的优点。
```

---

## 关键决策点

### 决策 1：生成几个策略？

太少（1个）→ 没有比较  
太多（5个以上）→ 成本太高  
**建议：** 2-3 个，覆盖不同方法类型

### 决策 2：策略之间要有多大的差异？

❌ 不好的例子：
  • 策略 A：用牛顿力学
  • 策略 B：也用牛顿力学，但用不同坐标系
  
✅ 好的例子：
  • 策略 A：解析方法（精确解）
  • 策略 B：数值方法（近似解）
  • 策略 C：估算方法（量级验证）

**原则：** 策略应该互补，而不是重复

### 决策 3：如果所有策略都失败了怎么办？

选项 A：生成新策略，再来一轮  
选项 B：标记为"无法解决"，人工介入  
**建议：** 最多重试 1 次，避免无限循环

## 什么时候用 Parallel Paths

✅ **适合的场景：**
- 问题有多种已知解法（如：力学问题可以用牛顿力学或拉格朗日力学）
- 想验证答案的正确性（多个独立方法得到相同结果）
- 想找到最优雅的解法（不只是正确，还要简洁）

❌ **不适合的场景：**
- 问题本身很模糊，连一个解法都想不出
- 计算资源有限（每个策略都要完整执行，成本 ×N）
- 时间紧迫（并行虽快，但总 token 消耗高）

---

## 与其他 Pipeline 的关系

**vs Standard：**
- Standard：一条路走到黑
- Parallel：多条路同时走，选最好的

**vs Tree Search：**
- Parallel：所有策略同时开始，独立完成
- Tree Search：策略有先后，根据前面的结果调整后面的

**什么时候选 Parallel，什么时候选 Tree Search？**
- 如果你对几个策略都有信心 → Parallel
- 如果你不确定哪个策略可行 → Tree Search

## 实际例子

**问题：** 求解带电粒子在电磁场中的运动

**策略生成：**
- 策略 A：解析求解运动方程（拉格朗日力学）
- 策略 B：数值积分（龙格-库塔法）
- 策略 C：漂移近似（绝热近似）

**执行结果：**
- 策略 A：得到解析解，包含贝塞尔函数，形式复杂
- 策略 B：数值轨迹，精度依赖步长
- 策略 C：简单近似，物理图像清晰但精度低

**比较选择：**
- 三个结果一致（相互验证）
- 选择策略 A 作为最终答案（精确）
- 用策略 C 的物理解释辅助理解

---

## 核心优势

1. **鲁棒性高** — 一个策略失败不影响其他
2. **交叉验证** — 多个独立方法得到相同结果，可信度高
3. **发现最优** — 不只是正确，还能找到最优雅的解法

## 主要代价

1. **成本高** — Token 消耗 ×N
2. **综合困难** — 需要额外的工作来比较和选择
3. **可能都错** — 如果问题理解错了，所有策略都会错
