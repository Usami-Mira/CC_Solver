# Debate — 多专家辩论

## 核心思想

"三个臭皮匠，顶个诸葛亮。"

复杂问题往往需要多个角度的分析。一个人可能只看到一面，但多个人从不同角度看，就能看到全貌。

就像真实的科研团队：
- 理论专家说："这个问题应该用拉格朗日力学..."
- 计算专家说："但数值模拟可能更直接..."
- 实验专家说："先做个量级估算看看..."
- 批评者说："等等，你们有没有考虑..."

通过辩论，最终达成共识。

---

## 流程图

```
第一步：独立分析
─────────────────────────────────
多位专家同时分析同一个问题，各自从自己的专业角度出发

理论专家 → 从物理原理分析
计算专家 → 提出数值方法
实验专家 → 提供直觉和估算
批评者 → 准备找漏洞


第二步：辩论交流
─────────────────────────────────
专家们互相评论：

批评者指出每个人的问题
  • "理论方法假设可分离变量，但这里不成立"
  • "数值方法没考虑边界条件"
  • "估算忽略了相对论效应"

专家们回应批评：
  • "我承认，但可以改用微扰论"
  • "边界条件可以这样处理..."
  • "相对论效应可以估算一下"


第三步：达成共识
─────────────────────────────────
经过 1-3 轮辩论，意见逐渐收敛

协调者综合各方意见：
  • 理论部分采用方案 A
  • 数值验证采用方案 B
  • 量级检查采用方案 C
  • 形成统一的执行计划


第四步：执行方案
─────────────────────────────────
基于共识计划，执行完整求解
```

## 关键概念

### 专家角色（Expert Roles）

每个专家有自己的专业视角：

**理论专家（Theorist）**
- 关注：物理原理、守恒律、对称性
- 方法：解析推导、理论分析
- 口头禅："从基本原理出发..."

**计算专家（Computationalist）**
- 关注：数值方法、算法设计、误差控制
- 方法：数值模拟、计算验证
- 口头禅："我们可以用数值方法求解..."

**实验专家（Experimentalist）**
- 关注：物理直觉、量级估算、实验验证
- 方法：back-of-envelope 计算、极限分析
- 口头禅："先估算一下量级..."

**批评者（Critic）**
- 关注：逻辑漏洞、假设检验、边界条件
- 方法：挑毛病、找反例
- 口头禅："但是..."

### 辩论轮次（Debate Rounds）

不是一次性的讨论，而是多轮迭代：

**轮次 1：** 批评者指出问题  
**轮次 2：** 专家们回应，修正自己的方案  
**轮次 3：** 批评者再次检查，确认没有重大遗漏  

通常 2-3 轮就能收敛。

### 共识（Consensus）

不是所有人都同意，而是：
- 主要分歧已经解决
- 没有明显的致命问题
- 形成了可执行的方案

## 关键决策点

### 决策 1：需要哪些专家？

**物理竞赛题：**
- 理论专家 + 计算专家 + 实验专家 + 批评者

**跨学科问题：**
- 物理专家 + 化学专家 + 数学专家 + 批评者

**工程问题：**
- 设计师 + 分析师 + 实验师 + 批评者

**原则：** 根据问题领域选择专家组合

### 决策 2：辩论什么时候结束？

**结束的信号：**
- 连续 2 轮批评者没有新意见
- 专家们的主要分歧已经解决
- 形成了可执行的共识计划

**继续的信号：**
- 批评者发现了致命问题
- 专家们还在激烈争论核心方法
- 还没形成统一计划

**保护：** 最多辩论 3 轮，避免无限循环

### 决策 3：如果无法达成共识怎么办？

**选项 A：** 协调者强制决策（选择多数人的意见）  
**选项 B：** 保留分歧，执行时并行验证  
**选项 C：** 升级到 Tree Search，系统性探索

## 什么时候用 Debate

✅ **适合的场景：**
- 跨领域问题（如：生物物理、量子化学）
- 复杂问题（需要多角度分析）
- 容易出错的问题（需要批评者找漏洞）
- 有多种合理方法的问题（需要比较选择）

❌ **不适合的场景：**
- 简单问题（杀鸡用牛刀）
- 有明确标准答案的问题（不需要辩论）
- 时间紧迫的问题（辩论耗时）

---

## 与其他 Pipeline 的关系

**vs Parallel Paths：**
- Parallel：多个方案独立执行，最后比较
- Debate：多个专家先辩论，达成共识后再执行

**vs Iterative：**
- Iterative：一个人迭代尝试
- Debate：多个人先讨论，再执行

**什么时候选 Debate，什么时候选 Parallel？**
- 如果问题复杂，需要先讨论清楚 → Debate
- 如果已经有几个明确方案，只需比较 → Parallel

## 实际例子

**问题：** 设计一个粒子加速器

**独立分析：**
- 理论专家：用相对论力学计算轨迹
- 计算专家：用数值模拟优化磁场分布
- 实验专家：估算所需能量和尺寸
- 批评者：准备找漏洞

**辩论轮次 1：**
- 批评者对理论专家："你没考虑辐射损耗"
- 批评者对计算专家："你的网格精度够吗？"
- 批评者对实验专家："同步辐射效应呢？"

**辩论轮次 2：**
- 理论专家："加入辐射修正项"
- 计算专家："细化网格，做收敛性检验"
- 实验专家："估算同步辐射功率"

**辩论轮次 3：**
- 批评者："看起来没问题了"
- 达成共识：理论计算 + 数值优化 + 实验验证

**执行：**
- 基于共识计划，分工执行

## 核心优势

1. **多角度分析** — 减少盲点
2. **早期发现问题** — 批评者在执行前就指出漏洞
3. **综合最优方案** — 融合多个专家的优点
4. **模拟真实科研** — 像真实的团队协作

## 主要代价

1. **成本高** — 多个专家 × 多轮辩论
2. **可能不收敛** — 需要协调者强制决策
3. **简单问题太重** — 杀鸡用牛刀
4. **专家定义困难** — 需要根据问题定制专家角色
